KobanCalendar 導入ガイド

自分の職場用のサイトをゼロから立ち上げる人が、最初に一度だけ行う作業（GitHub アカウント・配信・管理用トークンの発行）の手引きです。日々の更新は配信後に管理ガイドへ進んでください。

この作業はサイトをゼロから立ち上げる人が最初に一度だけ行うものです。すでにサイトが動いていて、管理用のトークンだけを渡された人は、ここは読まず管理ガイドの「接続する（初回のみ）」へ進んでください。
導入① GitHub アカウントを作る

github.com の「Sign up」から、無料アカウントを 1 つ作ります（画面の案内どおりに進めば数分です。プランは「Free（無料）」で十分）。すでにアカウントがある人はこの項目を飛ばして構いません。

登録に使うメールアドレスとパスワードは、担当者交代時の引き継ぎ資産になるので安全な場所に控えておいてください。可能なら二段階認証（2FA）も設定しておくと安心です。
できれば、このアカウントはこのサイトの運用専用にして、ほかのプロジェクト（リポジトリ）を置かないことをおすすめします。あとで発行する管理用の鍵（導入③）が、万一漏れても、被害をこのサイト 1 つに閉じ込められます。
導入② サイトを配信する（デプロイ）

「デプロイ」とは、プログラムをインターネット上に公開してサイトとして見られる状態にすることです。一度この設定を済ませれば、あとは管理画面で保存するだけで自動的に更新されます。この作業は最初の一度だけです。

1

テンプレートから自分のサイトを作る

配信元のページ（github.com/bn-k1/kobancalendar）を開くと、上部に緑色の「Use this template」（このテンプレートを使う）ボタンがあります。これを押し、「Create a new repository」を選びます。プログラム一式が、自分専用のサイトの土台としてコピーされます。

2

名前と公開範囲を決める

  • Repository name（リポジトリ名）: 好きな名前を付けます（例: kobancalendar）。この名前はサイトのアドレスの一部になります。
  • Owner（持ち主）: 自分のアカウントを選びます。
  • 公開範囲: 「Public」（公開）を選びます。無料アカウントでサイトを公開するには Public が必要です。

「Create repository」を押すと、自分専用のコピーができあがります。

3

公開先（Pages）を設定する

できたページの「Settings」（設定）タブ → 左メニューの「Pages」を開きます。「Source」（ソース）という項目を「GitHub Actions」に変更します。これがサイトの公開場所の指定です。

4

最初の配信を走らせる

「Actions」タブを開き、左の一覧から「Deploy to GitHub Pages」を選びます。右側の「Run workflow」ボタンを押し、もう一度「Run workflow」を押すと配信が始まります。行が緑色のチェックになれば成功です（数分かかります）。

5

サイトのアドレスを確認する

もう一度「Settings」→「Pages」を開くと、上部に「Your site is live at …」とサイトのアドレス（URL）が表示されます。これが利用者に配るサイトのアドレスです。開いてカレンダーが表示されれば、配信は完了です。

テンプレートから作ったサイトは、元のプログラムとは切り離された独立したものです。元の側でプログラムが改良されても自動では反映されません（安定して動き続ける利点でもあります）。最新の機能を取り込みたいときは開発者に相談してください。うまく緑にならず赤い「×」が出たときは、その行を開くと止まった箇所が出るので、判断が難しければ画面を見せて開発者に相談してください。
導入③ 管理用トークン（PAT）を発行する

管理画面から交番表やメニューを編集するには、Personal Access Token（パーソナル・アクセス・トークン、略して PAT）という「管理者用の鍵」が 1 つ必要です。導入①で作った、このサイト運用のためのアカウントから発行します。管理する人ごとに 1 本ずつ発行してください（誰の操作か分かり、辞めた人の鍵だけを無効にできます）。

この鍵は「このアカウントが持つ公開リポジトリを書き換える」権限を持ちます。だからこそ、導入①のアカウントはこのサイト専用にして、ほかのリポジトリを置かないでください。そうすれば、万一鍵が漏れても被害はこのサイト 1 つに限られます。
1

設定を開く

GitHub 右上の自分のアイコン →「Settings」（設定）を開きます。

2

開発者設定を開く

左メニューをいちばん下までスクロールし、「Developer settings」（開発者設定）を押します。

3

トークン作成を始める

「Personal access tokens」→「Tokens (classic)」を開き、「Generate new token」→「Generate new token (classic)」を押します（Fine-grained ではなく classic の方です）。

4

各項目を入力する

  • Note（名前）: 用途と担当者が分かる名前。例: kobancalendar-admin-tanaka
  • Expiration（有効期限）: 「No expiration」（無期限）を選びます。期限切れで管理画面が止まる心配がなくなります。※無期限の鍵は自動では失効しないので、担当交代のときは必ず後述の「Revoke」で無効にしてください。
  • Select scopes（権限）: public_repo だけにチェックを入れます（「repo」グループの中の項目です）。repo 全体や workflow など、ほかにはチェックを入れないでください。このサイトの更新に必要なのは public_repo だけです。
5

発行してコピーする

下の「Generate token」を押します。ghp_… で始まる文字列が表示されるので、その場でコピーします（このトークンは二度と表示されません。閉じる前に必ず控えます）。

登録のしかた: 発行したトークン文字列を、管理する本人に渡します。本人は管理ガイドの「接続する（初回のみ）」の手順で管理画面に貼り付けます。

トークンは鍵そのものです。メールやチャットに貼りっぱなしにせず、渡したら控えは安全に保管してください。担当を外れた人がいれば、その人のトークンを GitHub の同じ画面から「Revoke」（失効）で無効にします。

ここまで済んだらサイトは公開済みです。以降のトークン接続と日々の更新（交番表・独自の休日・表示ルール・食堂メニュー）は 管理ガイド に進んでください。
