KobanCalendar 管理ガイド

交番表・独自の休日・表示ルール・食堂メニューを、管理画面（#/admin）で日々更新するための手引きです。管理用のトークンを渡された人は「接続する（初回のみ）」から始めてください。

サイトをゼロから立ち上げる人（GitHub アカウント作成・配信・トークン発行）は、先に導入ガイドを済ませてください。このガイドは、サイトが配信済みで管理用トークンを持っている人向けです。
接続する（初回のみ）
1

管理画面を開く

ふだん見ているサイトのアドレスの末尾に #/admin を付けて開きます。「GitHub 接続」という画面が表示されます。

2

トークンを貼り付ける

渡された Personal Access Token（ghp_… で始まる文字列）を「Personal Access Token」欄に入力し、「保存して接続テスト」を押します。

3

接続を確認する

「✓ トークンは保存済みです。GitHub に接続できます。」と表示されれば完了です。この下に交番表・独自の休日・表示ルール・食堂メニューの管理パネルが並びます。

トークンはこの端末のブラウザにだけ保存され、どこにも送信・共有されません。別のパソコンやスマホからも管理したいときは、その端末でも同じトークンを貼り付け直してください（端末ごとに1回）。
保存すると配信される

それぞれの管理パネルには保存ボタンがあります（「保存して配信する」など、パネルごとに名前は少し違います）。押すと内容が GitHub に保存され、数分後には自動でサイトに反映されます。

保存ボタンを押したあと、ほかに何かする必要はありません。ファイルをアップロードしたり、コマンドを実行したりする作業は一切ありません。サイトへの反映は完全に自動です。この仕組みはどのパネルでも共通なので、以下の各項目では繰り返しません。
交番表・コマ位置表が変わったら

職場の掲示が新しくなったとき、まず「どちらの表が変わったのか」を見きわめます。このアプリで扱う表は次の2つだけです。

交番表 早番・遅番・夜勤・公休などの勤務の並び（コマ）と時刻そのものを並べた表です。このアプリが扱うのはこちらだけで、CSVで取り込みます。
コマ位置表 基準日の時点で各員が交番表の何コマ目にいるかを示す、職場に貼り出される表です。利用者はこれを見て自分の基準日のコマ位置をアプリに入力します。アプリはこの表そのものを持ちません。これが新しく貼り替わって全員のコマ位置がずれたときは、下の「1.」で有効日を更新して反映します。

この2つのどちらが変わったかで、次の3パターンのどれに当てはまるかを判断してください。「交番表の管理」パネルで操作します。

1. 交番表は同じで、コマ位置表だけが変わった場合

勤務の内容（早番・遅番・夜勤などの並び）は変わらないが、職場に新しいコマ位置表が貼られて全員のコマ位置が一斉にズレた場合（異動・組み替えなど）です。有効日（基準日）を更新して、この貼り替えをアプリに反映します。

「＋ 新しい世代を追加」を押し、「前の世代と同じ交番表を使う（コマ位置だけ変わる場合）」にチェックを入れます。フォルダ名やCSVの入力欄は消え、「有効日 (from)」だけ入力すればよくなります。新しい基準日を入力して保存すれば、いま使われている交番表（CSV）はそのまま引き継がれます。

2. 交番表・コマ位置表がともに変わった場合

すべての掲示物が変わる場合です。

同じく「＋ 新しい世代を追加」から、新しい「有効日 (from)」と新しい「フォルダ名」を入力し、平日・土曜・日祝の3つのCSVを新しい内容で取り込みます（ドラッグ＆ドロップ、または貼り付け）。プレビュー表で掲示の交番表と見比べてから「この内容で配信する」を押します。

3. コマ位置表は変わらないが、ある日から交番表の中身だけ差し替わる

世代（有効日）は増やさず、「現行」または「未来（新版）」の世代の行にある「＋ 途中で表を差し替え」を使います。回転の起点（有効日）が動かないので、利用者のコマ位置は途切れず、「新版/旧版」の切り替えも増えません。

差し替え日と新しいフォルダ名、3つのCSVを入力します。差し替える表は行数（コマの数）が元の交番表と同じでなければなりません。合わないと「コマ数が世代のコマ数と一致しません」と出て保存ボタンが押せません。

世代の状態

一覧の「状態」欄には次のバッジが出ます。

現行 いま使われている世代です。削除できません。
過去 前の世代です。基本的に削除して構いません。
未来（新版） まだ有効日が来ていない世代です。利用者側の基準日選択に「新版」として表示され、切り替えて事前に確認できます。

「削除」ボタンが押せないときは、現行世代であるか、次の世代がこの世代のデータを引き継いでいる（一覧に「（継承）」と表示されている）ためです。表示どおり「現行世代や継承元は削除できません」。

途中の表差し替え（「表差し替え」バッジの行）は、追加した世代自身とは別に「編集」「削除」できます。

未使用のデータフォルダ

どの世代からも参照されなくなったデータフォルダは、「未使用のデータフォルダ」として一覧の下に出ます。自動で消えることはありません。整理してよいという合図なので、不要なら「削除」を押して構いません。

独自の休日

祝日ライブラリに無い職場独自の休み（盆暮れなど）を追加します。年は無視され、月日だけが登録され、毎年くり返し適用されます。

日付を選んで「追加」を押すとチップが増えます。削除したい休日はチップの「×」を押します。「保存して配信する」を押すまでは確定しません。

表示ルール

予定名に含まれるキーワードで、カレンダー上の色が決まります。上のルールから順に判定し、最初に当たったものが勝ちます。だから並び順がそのまま優先順位で、行の「⠿」をドラッグするか、↑↓ボタンで入れ替えられます。

ルールに名前はありません。キーワードそのものがそのルールの目印です。

「全日空き」にチェックを入れると、そのキーワードに当てはまる予定の日は「飲みに行くンダー」で終日空いていると扱われます（公休・法休など）。

時刻を表示するかどうかの設定はありません。CSVに時刻があれば表示され、なければ表示されません。

「プレビュー」欄に予定名（例: 黄121）を入力すると、どのルールに当たって何色になるかがその場で分かります。

保存前に不備があると（キーワード未入力・色の形式不正など）、「保存して配信する」の上に理由が一覧で出ます。
食堂メニューの管理

A定食・B定食を月ごとに編集します（1行が1日分で、月の1日から順に並びます）。txt ファイルをドロップするか、内容を直接貼り付けます。

プレビュー表で掲示のメニューと見比べて、日付のズレがないか確認してください。空行はその日のメニュー無し、休みの日は「定休日」とそのまま入力します。

新しい月を登録するには「＋ 新しい月」から年月を選んで「追加」します。編集中（未保存の変更がある間）は月の切り替え・追加ができません。

ファイルが無い月は、利用者側には何も表示されません。

困ったとき
  • 保存ボタンが押せない → 未入力や不正な値があると、その理由が一覧で出ます。
  • 保存したのにサイトが変わらない → 配信のビルドに数分かかります。ブラウザの再読み込み（キャッシュ）も試してください。
  • 「読み込みに失敗しました」 → トークンに public_repo の権限が付いているか確認してください（無期限で発行していれば、期限切れの心配はありません）。
  • 表示ルールで「旧形式のままです」と出る → コードが古いままです。開発者に連絡してください。
